认证机制

系统采用 JWT 双令牌模式：Access Token 用于 API 请求，Refresh Token 用于续期。

Token 获取流程

用户输入账号密码 → POST /auth/login → 返回 accessToken + refreshToken → 前端存储 Token → 后续请求带 Authorization Header

Token 续期流程

Access Token 过期 (401) → 拦截器捕获 401 → POST /auth/refresh-token (带 refreshToken) → 获取新 accessToken → 重放原始请求

前端实现要点：

1. Access Token 存储建议：内存变量 + localStorage 备份；Refresh Token 存 localStorage
2. HTTP 拦截器：每个请求自动注入 Authorization: Bearer <accessToken>
3. 401 拦截：自动调用 refresh-token 续期并重放请求，续期失败则跳转登录页
4. 并发续期锁：多个请求同时 401 时，只发起一次 refresh，其余请求排队等待

统一响应格式

所有 JSON 接口返回统一的 ApiResult<T> 包装结构。

{
  "code": 200,           // 业务状态码，200=成功
  "message": "success",  // 描述信息
  "data": { ... },       // 业务数据载荷，失败时为 null
  "timestamp": 1726210000000  // 服务器时间戳（毫秒）
}

前端统一处理建议

codeHTTP Status含义前端处理
200200成功取 data 字段
400400参数错误展示 message
401401未认证/Token过期触发 refresh-token 流程
402402积分不足弹窗引导充值
403403无权限/越权展示权限不足提示
404404资源不存在展示 404 页面

axios 响应拦截器伪代码：

axios.interceptors.response.use(res => {
  if (res.data.code === 200) return res.data.data;
  return Promise.reject(res.data);
}, err => {
  if (err.response?.status === 401) { /* 触发 refresh */ }
  if (err.response?.status === 402) { /* 弹充值弹窗 */ }
  return Promise.reject(err);
});

SSE 事件类型

type触发时机前端处理
graph_initialized执行图规划完成渲染 DAG 节点拓扑图
node_ready节点就绪节点状态→READY
node_started节点开始执行节点状态→RUNNING（加载动画）

node_completed节点完成节点状态→SUCCEEDED

run_failed运行失败关闭 SSE，展示错误
run_cancelled运行被取消关闭 SSE，展示取消提示

POST /api/v1/auth/refresh-token 刷新访问令牌

使用 Refresh Token 换取新的 Access Token。Token 可通过 query 参数或请求头传递。

请求参数

来源位置字段必填
Query 参数?refreshToken=xxxrefreshToken二选一
请求头X-Refresh-Token: xxxheaderToken二选一

响应

同 AuthResponse 结构（含新的 accessToken 和 refreshToken）。

前端实现：此接口通常由 axios 响应拦截器在 401 时自动调用，用户无感知。建议通过请求头 X-Refresh-Token 传递，避免 URL 泄露 Token。

🔬 投研引擎（核心）

基础路径：/api/v1/research  |  鉴权：需认证（health 除外）

POST /api/v1/research/runs SSE 流式投研运行 Accept: text/event-stream

投研多智能体工作流的流式入口。通过 Accept 头区分 SSE 或 JSON 模式。SSE 模式返回 Flux<ResearchStreamEvent> 事件流。

同一路径两个模式：

• SSE 模式：Accept: text/event-stream → 返回事件流
• JSON 模式：Accept: application/json → 返回同步结果
前端通过设置 Accept 请求头来切换。

请求体（ResearchRunRequest）

字段类型必填说明
promptString必填自然语言投研问题（1-20000 字符）
sessionIdString可选会话 ID（多轮对话时传入相同值；为空自动生成）
enableThinkingBoolean可选深度思考模式（false=极速标准 deepseek-chat, true=深度推理 deepseek-reasoner）

SSE 响应

返回一系列 ResearchStreamEvent JSON 事件（见 SSE 事件格式）。

// 前端 SSE 消费伪代码
const response = await fetch('/api/v1/research/runs', {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json',
    'Accept': 'text/event-stream',
    'Authorization': `Bearer ${token}`
  },
  body: JSON.stringify({ prompt: '帮我筛选近三年回撤小于5%的债券基金', enableThinking: false })
});

const reader = response.body.getReader();
const decoder = new TextDecoder();
let buffer = '';

while (true) {
  const { done, value } = await reader.read();
  if (done) break;
  buffer += decoder.decode(value, { stream: true });
  const lines = buffer.split('\n');
  buffer = lines.pop();
  for (const line of lines) {
    if (line.startsWith('data:')) {
      const event = JSON.parse(line.slice(5).trim());
      handleStreamEvent(event); // 分发到 UI
    }
  }
}

const useAuthStore = defineStore('auth', () => {
  const accessToken = ref(localStorage.getItem('accessToken') || '')
  const refreshToken = ref(localStorage.getItem('refreshToken') || '')
  const user = ref(null)
  const isAuthenticated = computed(() => !!accessToken.value)
  const isAdmin = computed(() => user.value?.roles?.includes('ADMIN'))

  async function login(req) { /* POST /api/v1/auth/login */ }
  async function register(req) { /* POST /api/v1/auth/register */ }
  async function refreshAccessToken() { /* POST /api/v1/auth/refresh-token */ }
  function logout() { /* clear tokens, redirect to /login */ }
  return { accessToken, refreshToken, user, isAuthenticated, isAdmin, ... }
})

// stores/wallet.ts
const useWalletStore = defineStore('wallet', () => {
  const balance = ref(0)
  const walletStatus = ref('NORMAL')
  const estimatedReports = ref(0)
  async function fetchWallet() { /* GET /api/v1/billing/wallet */ }
  return { balance, walletStatus, estimatedReports, fetchWallet }

关键注意事项：

1. SSE 消费必须用 fetch：投研运行是 POST 请求，EventSource 不支持 POST 方法和自定义 Header
2. 402 拦截：axios 拦截器捕获 402 状态码，弹出充值引导弹窗
3. 余额实时更新：每次投研消耗后刷新钱包余额（SSE run_completed 事件后）
4. CORS：后端当前仅放行 OPTIONS，开发环境需配置 Vite/Webpack 代理或后端添加 @CrossOrigin 配置
